## A1 — UTF-8 BOM

**Шалтгаан.** Windows Notepad-ийн "UTF-8 with BOM" файлын эхэнд `EF BB BF` байт байдаг. Parser эдгээрийг нэрийн нэг хэсэг гэж уншиж, нэрийг буруу гэж үзэж байсан.

**Засвар.** `src/driver.c` нь эхний мөрийн эхэнд BOM байвал алгасна. Шалгах функц нь `src/utf8.c`-ийн `utf8_has_bom()`.

| | `printf '\xef\xbb\xbfT1, 4, 20\n' > bom.txt; ./fcfs bom.txt` |
|---|---|
| Өмнө | `error: line 1: invalid task name '﻿T1' …` |
| Дараа | Хэвийн ажиллана, avg WT 0.00 |

## A2 — Кирилл нэр

**Шалтгаан.** Нэрийг `isalnum()`-ээр шалгадаг байсан тул зөвхөн ASCII үсэг зөвшөөрөгдөж байсан. Мессеж дэх "letters" гэсэн үг үүнийг тодорхой илэрхийлээгүй.

**Засвар.**
- **Нэрийн шалгалт (`src/driver.c`).** Нэрийг UTF-8-аар задалж, латин үсэг, тоо, `_ - .` болон кирилл үсгийг (U+0400–U+04FF, Монгол Ө ө Ү ү орно) зөвшөөрнө. Буруу UTF-8, бусад бичгийн үсэг, emoji-г татгалзана. 31 тэмдэгтийн хязгаарыг байтаар биш тэмдэгтээр тоолно.
- **Нэрийн буфер (`src/task.h`).** UTF-8 нэр багтахаар томсгосон: `MAX_NAME_BYTES`.
- **Терминалын гаралт (`src/stats.c`).** Gantt болон хүснэгтийн зэрэгцүүлэлтийг тэмдэгтийн тоогоор хийдэг болгосон.
- **UI сервер (`ui/server.py`).** C-ийн гаралтыг locale-оос үл хамааран UTF-8-аар уншина.
- **Алдааны мессеж.** `invalid task name '…' (use Latin or Cyrillic letters, digits, _ - ., at most 31 characters)`.
- **Баримт бичиг.** Manual 1.4, 1.8 болон README-д зөвшөөрөгдөх хүрээг бичсэн.

| | `Процесс1, 4, 20` |
|---|---|
| Өмнө | `error: line 1: invalid task name 'Процесс1' (use letters, digits, _ - ., …)` |
| Дараа | Ажиллана. Gantt, хүснэгт, JSON, UI-д `Процесс1`, `Өгөгдөл_2`, `Үйлдэл-3` зөв харагдана |

Хил дээрх тохиолдол:

| Оролт | Үр дүн |
|---|---|
| 31 кирилл тэмдэгт | OK |
| 32 кирилл тэмдэгт | Алдаа |
| `T\xff1` (буруу UTF-8) | Алдаа |
| `任务` (хятад үсэг) | Алдаа |
| `T😀` (emoji) | Алдаа |
| Давхардсан кирилл нэр | `duplicate task name` |

## A3 — Харьцуулалтад нэг алгоритмын алдаа

**Шалтгаан.** `ui/app.js` нь `/api/compare`-ийн 5 үр дүнгийн аль нэг нь алдаатай бол харьцуулалтыг бүхэлд нь цуцалдаг байсан.

**Засвар.**
- **`ui/app.js`.** Амжилттай үр дүнгүүдийг харьцуулна. Ажиллаагүй алгоритм бүрийг нэр, шалтгаантай нь анхааруулга болгон харуулна. 5 алгоритм бүгд алдаатай бол (оролт өөрөө буруу) өмнөх шиг ганц алдаа харуулна.
- **`ui/compare.js`.** Хүснэгтэд "✖ ажиллаагүй: …" мөр нэмнэ.
- **Жижиг засвар.** Bar chart-ын шошгыг "★" болгож богиносгосон. Урт утгатай үед "хамгийн бага" гэсэн үг таслагддаг байсан.

**Шүүмжийн тохиолдол** (`A, 5, 300000`, q = 1, "Бүх алгоритмыг харьцуулах"):

| | Үр дүн |
|---|---|
| Өмнө | Зөвхөн `quantum too small` алдаа гарч, харьцуулалт харагдахгүй |
| Дараа | FCFS, SJF, Priority-ийн мини Gantt, bar chart, хүснэгт харагдана. RR, Priority-RR нь "✖ ажиллаагүй: quantum too small …" мөрөнд гарна |

## A4 — Идэвхгүй quantum талбар

**Шалтгаан.** `runSelected()` алгоритмаас үл хамааран `readQuantum()`-г үргэлж дууддаг байсан.

**Засвар (`ui/app.js`).** Шүүмжийн хоёр саналыг хоёуланг нь хэрэгжүүлсэн:
- Quantum-ыг зөвхөн RR, Priority-RR болон харьцуулалтад шалгана.
- RR-ээс өөр алгоритм руу шилжихэд талбарт буруу утга байвал анхдагч 10 болгоно. Талбар идэвхгүй тул хэрэглэгч засаж чадахгүй.

RR өөрөө 0, 4.5 зэрэг буруу утгыг өмнөх шигээ татгалзана.

| | RR → q = 0 → FCFS → Ажиллуулах |
|---|---|
| Өмнө | `Time quantum нь 1-ээс 1000000 … (одоо: "0")`, FCFS ажиллахгүй |
| Дараа | Талбар 10 болж, FCFS ажиллана |
